현업에서 발견한 문제

작은 불편도 직접 고치기 시작했습니다

저도 베트남어를 배우던 학생이었고, 지금은 학생들을 가르치며 학습 운영을 맡고 있습니다. 학생은 학습자료를 읽고 과제를 제출하려고 여러 채널을 오가야 했고, 운영진은 흩어진 기록과 피드백을 찾아 엑셀에 다시 옮겨 적었습니다.

필요한 기능을 만들려면 개발자에게 문제를 설명하고, 구현된 결과를 다시 확인해야 했습니다. 기획·디자인·개발 인력을 따로 두기 어려운 환경에서 작은 불편까지 계속 개선하기는 쉽지 않았습니다. AI 에이전트를 활용하면서 제가 사용자 흐름과 화면을 정하고, 구현과 검토를 요청하며 직접 개선해 나가기 시작했습니다.

저에게 AI는 결과물을 빨리 만드는 도구라기보다, 현장에서 찾은 문제를 미뤄 두지 않고 직접 풀어 볼 수 있게 해 준 도구입니다.

학생이 어떤 순서로 공부하고 제출할지, 운영진에게 어떤 정보가 먼저 보여야 할지를 직접 정했습니다. AI가 만든 화면도 실제로 눌러 보며 확인하고, 현장의 피드백을 받아 다시 고쳤습니다.

한 사람의 목표에 맞춘 언어 학습

현재 실력과 학습 스타일, 하루에 공부할 수 있는 시간, 목표 시험일까지 남은 기간을 함께 살펴 개인별 커리큘럼과 하루 학습량을 정하는 LMS를 만들고 싶습니다. 학습자가 매번 무엇을 공부할지 고민하지 않고, 접속하면 그날 필요한 학습을 시작할 수 있는 환경입니다.

매일 접속하면 이어지는 학습

예습·학습·복습부터 단어 정리, 테스트와 모의고사, 원어민 전화·채팅 수업까지 하나의 흐름으로 연결하려 합니다. 목표 날짜에 맞춰 학습량을 정하고, 학습 기록과 테스트 결과를 바탕으로 다음에 공부할 내용을 조정하고 싶습니다.

학습 기록으로 효과 확인

어떤 자료와 학습 방식이 각 사람에게 도움이 되는지 기록으로 살펴보고 싶습니다. 이 데이터를 바탕으로 개인의 학습 유형을 더 빠르게 파악하는 AI를 만들고, 추천한 내용이 실제 실력 향상으로 이어지는지도 확인하려 합니다.

AIGEN에서 배우고 싶은 것

지금까지는 교육 현장의 경험을 바탕으로 서비스를 혼자 기획하고 AI와 구현해 왔습니다. AIGEN에서는 다른 배경의 동료, 전문가와 함께 문제를 정의하고 데이터를 활용하는 방법을 배우고 싶습니다. 특히 학습 효과를 어떻게 평가하고, 그 결과를 다음 개선으로 연결할지 더 체계적으로 다루고 싶습니다.

업무 환경을 바꾸는 AX

회사에 쌓인 데이터를 실무자가 쉽게 찾고 이해하도록 돕는 AX에도 관심이 있습니다. 자료를 반복해서 찾아 옮겨 적는 일을 줄이고, 필요한 정보를 한눈에 보고 판단할 수 있도록 만들고 싶습니다. 통합 DB에서 시작한 경험을 회사의 다른 업무로 넓혀가려 합니다.

개인 맞춤 커리큘럼과 학습 유형 평가 AI는 앞으로 만들고 검증할 구상입니다.

통합 DB

흩어진 학습 기록을 한곳에서 확인하도록.

선생님의 입력부터 학생과 운영진의 조회까지, 학습 기록이 이어지는 흐름을 만들었습니다.

단독 1인 개발 · AI 활용2026.06.03 — 2026.06.26
01

만들게 된 이유

과제 제출 여부는 엑셀에 직접 표시하고, 선생님의 피드백은 파일로 받았습니다. 운영진은 자료를 열고, 옮겨 적고, 다시 대조해야 했습니다.

학생도 본인의 학습 현황을 확인하려면 기록을 찾아보거나 담당 선생님에게 문의해야 했습니다. 입력과 조회를 한 흐름으로 연결하고 싶었습니다.

02

입력하는 사람과 확인하는 사람을 나눴습니다

선생님은 수업 평가를 입력하고, 운영진은 학생들의 학습 현황을 함께 살펴보며, 학생은 본인 기록을 확인하도록 화면과 사용자 흐름을 정했습니다.

선생님 입력→학습 기록 통합→학생·운영진 조회
03

제가 흐름을 정하고, AI와 구현했습니다

기존 자료와 화면 캡처, 예시 데이터를 바탕으로 필요한 화면을 정리했습니다. 데이터 구조와 사용자 흐름을 직접 정하고, 코드 작성과 기술 검토에 AI를 활용했습니다.

AI가 만든 화면은 실제로 눌러 보며 확인했습니다. 학생 화면과 운영자 화면에서 필요한 정보가 각각 보이는지 검토하고, 현장의 피드백을 받아 수정했습니다.

04

역할에 따라 필요한 정보가 보이도록

학생은 과제 제출 현황과 전화수업 피드백을 확인합니다. 운영진은 대시보드에서 학생별 과제 상태와 평가 기록을 함께 살펴봅니다.

  • 학생: 본인 학습 현황과 피드백 확인
  • 선생님: 주차별 수업 평가 입력
  • 운영진: 학생별 기록과 과제 상태 조회
05

피드백을 다음 수정으로 연결했습니다

“전에는 매주 내용을 제가 따로 메모해야 했는데, 이렇게 주차별로 입력하니 훨씬 낫네요.”원어민 선생님 · 2026.07.29

주차별로 피드백을 다시 보고 싶다는 요청을 받아, 그날 수정과 다시 보기 기능을 더했습니다.

06

만든 뒤에도 기록을 지키는 기준이 필요했습니다

잘못된 과제 수나 중복된 강의 구간이 들어왔을 때 기존 정상 집계를 덮어쓰지 않도록 처리했습니다. 화면이 편리해지는 것과 기록이 정확하게 유지되는 것을 함께 확인해야 했습니다.

운영 코드에 반영한 내용과 실제 데이터의 복구 확인은 구분해 기록했습니다.

07

현장에서 정한 기록 보존 기준

해외에서 연결이 끊겨 평가 저장이 실패하면 입력을 기기에 보관하고 연결이 돌아온 뒤 다시 전송하는 방향을 정했습니다. 사진이 실패했다고 평가 전체를 다시 작성하지 않도록 평가 저장과 사진 재시도도 분리했습니다.

종료된 과정은 학생 기록을 삭제하지 않고 조회 목록에서 구분하도록 했습니다. 실무자의 역할에 맞게 학생·선생님·운영진의 화면과 기간별 조회 범위도 나눴습니다.

08

AI와 구현하고 실패 상황을 확인하다

저는 현장의 요구와 기존 기록을 지키는 기준을 정했습니다. AI는 코드 초안과 독립 검토, 통합과 검사에 활용했고, 운영진은 오류와 불편을 알려 주었습니다. 네트워크 실패와 중복 전송, 조회 오류를 각각 확인하며 개선했습니다.

저장 복구와 조회 안정화는 작업 기록에 남아 있지만, 당시 실제 베트남 네트워크와 아이폰에서의 복구까지 확인한 것은 아닙니다. 자동 검사 결과를 무장애나 업무시간 절감률로 바꿔 쓰지 않습니다.

기획 / 발견한 문제

기록을 찾고 옮기는 시간이 학생을 살피는 시간보다 길어졌습니다.

과제 제출 기록, 발음 코칭과 전화수업 평가는 여러 시트와 파일에 나뉘어 있었습니다. 운영진은 전달받은 내용을 열어 확인한 뒤 엑셀에 옮겨 적고 다시 대조했습니다. 학생도 자기 제출 현황이나 선생님의 피드백을 보려면 기록을 찾거나 담당 선생님에게 문의해야 했습니다.

현장에서 이 흐름을 가까이 보며, 한 번 입력한 기록이 필요한 사람에게 이어지도록 만들고 싶었습니다. 기록을 정리하는 화면 하나만 만드는 것이 아니라, 선생님의 입력부터 학생과 운영진의 확인까지 사용자별 흐름을 연결하는 것이 출발점이었습니다.

기획 / 판단

같은 데이터라도 사람마다 필요한 화면은 다릅니다.

학생은 자신의 학습 현황과 전화수업 피드백을 확인하고, 선생님은 주차별 평가를 입력하며, 운영진은 학생별 과제와 평가를 함께 살펴보도록 역할을 나눴습니다. 기간별 제출률은 운영진이 확인하는 범위로 두었습니다.

편리하게 조회하는 만큼 기존 기록을 지키는 것도 중요했습니다. 중복된 강의 구간이나 잘못된 과제 수가 들어오면 정상 집계를 덮어쓰지 않고 이전 값을 유지하는 기준을 세웠습니다. 종료된 과정도 삭제하지 않고 상태를 구분해 필요할 때 다시 조회하도록 했습니다.

개발 / 입력과 조회

구글 시트의 기록을 역할별 화면으로 연결했습니다.

Google Sheets의 원본을 바탕으로 Apps Script에서 기록을 정리·조회하고, 학생과 운영진이 각자의 화면에서 확인하도록 구성했습니다. 저는 필요한 정보와 순서, 사용자 흐름과 화면을 직접 정하고 코드 작성·검토에는 AI를 활용했습니다.

해외에서 네트워크가 끊겨 저장이 실패할 수 있다는 운영 환경도 고려했습니다. 평가 입력을 기기에 먼저 보관하고 연결이 돌아오면 다시 전송하도록 했으며, 사진 업로드가 실패했다고 평가 전체를 다시 작성하지 않도록 평가 저장과 사진 재시도를 나눴습니다.

운영 / 검증과 개선

불편을 고친 뒤에도 실패할 때 기록이 남는지 확인했습니다.

운영진과 선생님이 알려 준 불편을 바탕으로 주차별 피드백 다시 보기와 수정 흐름을 개선했습니다. 한 원어민 선생님은 매주 따로 메모하던 내용을 주차별로 입력할 수 있어 훨씬 낫다는 의견을 주셨습니다.

저장 복구, 중복 방지와 조회 안정화는 작업 기록과 검수 자료에서 확인됩니다. 일부 검사는 예시 데이터를 사용했으며, 실제 베트남 네트워크나 아이폰에서의 복구까지 모두 확인한 것은 아닙니다.

03 / 전환

작은 불편도 직접
고치기 시작했습니다.

필요한 기능을 만들려면 개발자에게 문제를 설명하고, 구현된 결과를 다시 확인해야 했습니다. 기획·디자인·개발 인력을 따로 두기 어려운 환경에서 작은 불편까지 계속 개선하기는 쉽지 않았습니다.

저에게 AI는 결과물을 빨리 만드는 도구라기보다, 현장에서 찾은 문제를 미뤄 두지 않고 직접 풀어 볼 수 있게 해 준 도구입니다.

기획 / 출발점

베트남어를 공부하는 사람에게도, 가볍게 시작할 수 있는 테스트가 필요했습니다.

베트남어는 다른 언어에 비해 학습자가 쉽게 참여할 수 있는 테스트와 서비스가 많지 않았습니다. 단어를 얼마나 알고 있는지 궁금해도 먼저 가입하거나 긴 시험을 치러야 한다면 시작 자체가 부담이 될 수 있습니다.

그래서 누구나 무료로 참여할 수 있고, 짧은 시간 동안 게임처럼 단어를 맞추며 현재 수준을 살펴볼 수 있는 경험을 만들고 싶었습니다. 결과를 본 뒤에는 내 수준에 맞는 수업과 앞으로의 학습 방향까지 확인할 수 있도록 기획했습니다.

기획 / 판단

참여하기 쉽게 만들고, 결과에서 다음 행동을 안내합니다.

첫 화면에서는 무료 테스트라는 목적과 참여 방법을 이해할 수 있게 하고, 로그인 없이 시작해 60초 동안 베트남어와 한국어 단어를 맞추도록 흐름을 정했습니다. 짧은 매칭은 학습자가 현재 아는 단어를 부담 없이 돌아보는 출발점입니다.

결과를 숫자로만 끝내지 않고 씨앗·새싹·줄기·꽃·열매의 다섯 단계로 보여줍니다. 저는 결과에서 커리큘럼을 먼저 살펴보게 하고 강점을 구분하는 색상을 통일하도록 요청했습니다. 학습자가 결과를 읽고 자신의 다음 학습을 선택하기 쉽게 하려는 판단이었습니다.

개발 / 구현과 검수

단어 데이터, 매칭, 결과 안내를 한 흐름으로 연결했습니다.

제가 사용자 흐름과 화면을 정하고, AI에 구현과 기술 검토를 요청했습니다. 단어 데이터와 카드의 선택·매칭 상태를 연결하고, 테스트가 끝나면 결과 안내와 추천 수업으로 이어지게 했습니다. 기존 학습 내용과 판정 기준을 보존하면서 PC와 모바일에서 같은 기능을 제공하도록 배치를 조정했습니다.

개발본에는 1,705개 단어와 다섯 단계 판정을 검증한 기록이 있습니다.

결과 / 다시 살필 점

완료한 경험과 상담으로 이어진 행동을 따로 봅니다.

2026년 11월 9일 기준 누적 방문 4,453회, 테스트 완료 2,894건, 무료 상담 버튼 클릭 61건을 기록했습니다. 상담 클릭과 구매는 별개이며, 참여가 다음 학습으로 이어지는 흐름은 계속 개선하고 있습니다.

테스트에 참여한 사람이 끝까지 마치는 것과, 결과를 보고 상담 버튼을 누르는 것은 서로 다른 행동입니다. 결과 안내가 학습자가 다음에 할 일을 이해하는 데 도움이 되는지 계속 살펴보려 합니다.

기획 배경

학습과 운영을 하나의 흐름으로

이전에는 학습자료 전달과 과제 제출이 카카오톡 대화에 섞여 있었고, 운영진은 제출 여부를 시트에 다시 입력했습니다. 학생이 학습부터 제출까지 이어가고 운영진이 검수 상태를 확인할 수 있도록 전용 LMS를 기획했습니다.

사용자 흐름

학생의 하루와 운영진의 검수

학생은 로그인 후 오늘의 학습자료와 음원을 확인하고 문장과 녹음을 제출합니다. 운영진은 제출물을 확인하고 보완 요청과 미션 인정을 따로 처리합니다. 제출과 인정은 다른 상태이므로 과제를 보냈다는 이유만으로 인정 처리하지 않습니다.

개발 과정

화면에서 운영 규칙으로

학습자와 운영자의 유저플로우와 와이어프레임을 먼저 정하고, 학습·제출·검수 화면을 연결했습니다. 이후 제출 상태와 일차별 콘텐츠 공개 기준을 정리하고 모바일 녹음과 재생, 공지와 메모를 보완했습니다. 화면과 API를 같은 Next.js 서비스에서 운영하고 데이터와 파일을 각각 Firestore와 Cloud Storage로 분리하는 구조를 택했습니다.

기존에 공유된 과정 주소를 유지해 새 기능 때문에 학생이 쓰던 링크가 끊기지 않도록 했습니다. 코드 작성과 기술 검토에 AI를 활용하면서 화면과 운영 기준은 직접 확인했습니다.
